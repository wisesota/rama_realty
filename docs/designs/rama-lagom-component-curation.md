## Problem Statement

Rama already has a distinctive Quiet → Converse → Confirm public experience, but the team wants to learn from ReUI, Motion Primitives, Magic UI, and Tailark without producing a generic component-library collage. The redesign must improve orientation, state continuity, and long-scroll craft while preserving a server-rendered public narrative, bilingual parity, evidence truth, and a restrained Nordic Lagom visual language.

## Status Quo

- The public landing is a 13,000-plus-pixel editorial narrative with a strong centered residential hero, project-owned evidence planes, a sticky specimen, native voice dialog, and EN/AR copy.
- Magic UI-inspired `ScrollProgress` and `ProgressiveBlur` primitives are already implemented in a restrained project-owned form.
- Motion already owns Decision Aperture state changes and GSAP owns bounded landing choreography.
- Existing unused showcase experiments such as bento and marquee patterns are not imported into production.
- Header anchors do not expose scroll-aware `aria-current`, and changing voice states replace content abruptly.

## Target User and Narrowest Wedge

The immediate user is a Dubai home buyer trying to turn a natural-language brief into inspectable criteria without mistaking illustrative atmosphere for inventory. The narrowest valuable change is better orientation through the long page and calmer continuity while voice states change. It is not a new template, a new theme, or more decorative animation.

## Constraints

- Preserve Source Serif 4, Instrument Sans, Noto Sans Arabic, the existing token pipeline, and Rama's repository-owned shadcn registry.
- Preserve light-only Nordic Lagom styling, native dialog semantics, reduced-motion stability, no-JavaScript public narrative, and 44px targets.
- Do not add premium dependencies, vendor API keys, testimonials, partner logos, ratings, market claims, or live-inventory implications.
- Do not animate Arabic characters independently or introduce infinite motion, cursor effects, glass, gradient text, pill-heavy chrome, or decorative particle fields.
- Keep public-route JavaScript within the existing release budget.

## Definitions and decision rules

- **Catalog snapshot**: the four official documentation URLs listed in [the dated component audit](../UI_LIBRARY_COMPONENT_AUDIT.md), observed on 2026-08-25. Later vendor additions do not retroactively fail this slice.
- **Adopted**: an equivalent governed Rama primitive is already in production.
- **Adapt**: implement the useful behavior as tokenized Rama-owned source.
- **Defer**: a plausible later operational use exists, but no current buyer problem justifies shipping it.
- **Reject**: the component conflicts with product truth, accessibility, RTL, performance, or Lagom restraint.
- **44px target**: every pointer-operable control has a minimum 44 by 44 CSS-pixel hit area. Its visible mark may be smaller when the hit area remains clear and non-overlapping.
- **Existing release budget**: public-route JavaScript may increase by no more than 15KB gzip and CSS by no more than 8KB gzip from the recorded production-build baseline in `docs/performance-baseline.json`. Run `pnpm performance:baseline -- --url http://localhost:3100/en --runs 5 --output docs/performance-after-library-curation.json`; compare `profiles.desktop.median.javascriptBytes` and `cssBytes`, plus the mobile equivalents, against the same fields in the baseline. The measurement is transfer bytes reported by Lighthouse, so the gate is conservative relative to gzip-only route chunks.

## Premises

1. More library components would make Rama less distinctive; only components that solve an observed buyer problem earn adoption.
2. Vendor source is reference material. Rama-owned, tokenized, RTL-aware adaptations remain the production source of truth.
3. Existing semantic HTML beats animated replacements when the replacement weakens accessibility or no-JavaScript behavior.
4. Motion is valuable for state continuity and orientation, not spectacle.
5. The best Tailark and ReUI contribution is composition and information architecture, not their themes or full-page templates.

## Approaches Considered

### Approach A: Minimal retention

Keep the current interface and only document the catalog audit. This is the smallest diff and lowest risk, but it leaves scroll orientation and voice-state continuity unresolved.

### Approach B: Curated Rama adaptations

Add scroll-aware current-section semantics to the existing header, add a small project-owned state-transition primitive for voice content, retain the purposeful Magic UI-inspired overflow and progress cues, and document Tailark/ReUI composition mappings. This improves the lived interface without changing product architecture or visual identity.

### Approach C: Vendor-led surface rebuild

Install registries and assemble the landing from vendor heroes, feature blocks, animated text, bento grids, marquees, and templates. This ships visual novelty quickly but creates theme drift, duplicate primitives, larger client bundles, weak RTL parity, and the recognizable look of an AI-assembled template.

## Recommended Approach

Approach B. It treats the four catalogs as a pattern library, not an identity system. The selected ideas are quiet, observable improvements: buyers know where they are, voice-state changes feel continuous, scrollable dialog content is legible, and existing comparison/timeline surfaces gain explicit lineage.

### Bounded implementation slice

- **Routes**: `/en` and `/ar`. The root localized redirect is unchanged and included only in regression coverage. Decision Room and staff surfaces are not changed in this slice.
- **Observed anchors**: `#specimen`, `#method`, and `#boundaries`, matching the existing primary-navigation links.
- **Catalog artifact**: `docs/UI_LIBRARY_COMPONENT_AUDIT.md` records the disposition and lineage for the four catalogs. Comparison/timeline lineage is documentation-only; their runtime behavior is unchanged.
- **Retained behavior**: the existing `ProgressiveBlur` dialog overflow cue and CSS `ScrollProgress` are verified but not redesigned.

### Scroll-aware navigation contract

1. On hydration, a recognized `location.hash` sets the matching link active immediately. An unrecognized or absent hash leaves all links inactive while the hero is visible.
2. An `IntersectionObserver` observes the three target sections through a narrow upper-viewport band using `rootMargin: "-18% 0px -70% 0px"` and threshold `0`.
3. When more than one target intersects, choose the section whose top is closest to 18% of the viewport. DOM order breaks exact ties.
4. When the observer has no intersecting entry below the hero, retain the most recent valid section. Returning above the first observed section clears the active state.
5. Navigation clicks set the intended state immediately; native hash navigation owns scroll, Back/Forward, and history. Keyboard focus intentionally remains on the activating link while the destination scrolls into view. The observer may update state after the destination enters its band.
6. Active links expose `aria-current="location"` and one restrained one-pixel visual marker. Focus remains a separate, higher-contrast outline.
7. Without JavaScript, anchors still work and no false current state is rendered.

### Semantic state-transition contract

```ts
type StateTransitionProps = {
  state: string;
  children: React.ReactNode;
  className?: string;
};
```

- Scope is the already-client public voice conversation panel only.
- The component owns no transcript or voice state; the existing parent remains canonical, so interruption cannot discard content.
- A keyed child enters with no more than 4px of `translateY` and crossfades over the existing 150ms semantic duration. Height is never tweened.
- `AnimatePresence` uses `mode="wait"`, so outgoing and incoming copies never coexist. The transitioned region contains no focusable controls.
- Rapid changes use latest-render-wins semantics: while an exit completes, obsolete intermediate visual states are not queued and only the latest parent state may enter.
- Existing `aria-labelledby`, `aria-describedby`, and the separate polite live region remain authoritative; the transition wrapper does not add another live region.
- Reduced motion renders a normal `div` and swaps immediately with no initial, exit, or layout animation.
- Dynamic copy remains inside the dialog's bounded scroll body; layout change is immediate and contained rather than animated.

## Open Questions

- A real-user observation session is a post-build product-validation activity, not an implementation-approval gate.

## Success Criteria

- Every named component or block category in the 2026-08-25 public catalog snapshot has an explicit adopt, adapt, defer, or reject disposition.
- Header navigation sets `aria-current="location"` while the corresponding public section is active and remains correct after direct hash navigation.
- Public voice-dialog state changes crossfade without height animation, transcript loss, or character splitting.
- Reduced motion renders stable final states with no Motion or GSAP transition execution or timing dependency.
- No new theme, font, ungoverned color, premium credential, unsupported claim, or template page enters production.
- EN and AR pass desktop/mobile, keyboard, overflow, and reduced-motion browser checks.
- `pnpm registry:build`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build` pass.

### Browser validation matrix

- EN/LTR and AR/RTL at 390x844 and 1440x900, plus the existing full responsive matrix at 320, 390, 768, 1024, 1280, and 1440px.
- Chromium automated coverage plus manual Arabic screen-reader smoke tests are retained as release evidence: NVDA with Chrome on Windows and VoiceOver with Safari on macOS. Local handoff records the available Windows result; production release requires both supported combinations.
- Keyboard: skip link, navigation, both hero actions, dialog Escape, and focus restoration.
- Assert no horizontal overflow, no image-load layout shift, distinct focus/current indicators, native Back/Forward hash behavior, and no duplicate live announcements.
- Under `prefers-reduced-motion: reduce`, the state copy swaps immediately and all public content remains visible.
- Measure bundle changes from a production build; reject the change if the public route exceeds +15KB gzip JavaScript or +8KB gzip CSS.

## Distribution Plan

`StateTransition` is published as the `state-transition` UI item in `registry.json`, and `voice-discovery-dialog` declares it as a registry dependency. Scroll-aware navigation remains inside the existing `site-navigation` registry item; it is not a new route-local artifact. `pnpm registry:build` generates `public/r/state-transition.json` and updates dependent artifacts; generated `public/r` files remain build outputs.
